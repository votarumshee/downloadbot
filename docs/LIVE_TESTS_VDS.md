# Проверка на отдельном VDS — 13 ноября 2026

Развёрнуто: Ubuntu 26.04 LTS, Docker Engine 29.9.3, Compose 5.7.1,
PostgreSQL 18, Python 3.12, yt-dlp 2026.10.26 + EJS, Node 24, FFmpeg.
Первый прогон проверял развёртывание версии 0.1.0. После подключения Telegram
добавлены подготовка совместимого MP4 и выдача через `sendVideo`; результаты ниже.

## Сеть и готовность

- SSH-вход отдельным ключом проверен; ключ сервера закреплён для следующих входов.
- YouTube, X, Instagram, Vimeo, Telegram, GitHub и Docker Registry доступны
  с VDS по HTTPS. На этапе проверки сетевых таймаутов не было.
- PostgreSQL, API и worker запущены и имеют статус `healthy`.
- `/readyz` возвращает `200 {"status":"ready"}`.
- API доступен через локальный SSH-туннель; его порт и PostgreSQL не открыты наружу.

## Реальные загрузки

Клиент создал задания через HTTP API по SSH-туннелю и получил успешные
результаты через авторизованный endpoint выдачи файлов. Ни cookies, ни mock
загрузчики не использовались.

| Сервис | Публичный пример | Итог |
|---|---|---|
| YouTube | `https://www.youtube.com/watch?v=jNQXAC9IVRw` | `failed / auth_required`: сервис требует сессию для проверки «не бот» |
| X | `https://x.com/captainamerica/status/719944021058060289` | `succeeded`, 184 236 байт |
| Instagram | `https://www.instagram.com/reel/Chunk8-jurw/` | `succeeded`, 918 120 байт |
| Vimeo | `https://vimeo.com/22439234` | `succeeded`, 20 459 880 байт |

Все три полученных файла полностью декодированы FFmpeg с запрещёнными сетевыми
протоколами: exit code 0, stderr пуст. HTTP-клиент проверил размеры файлов,
сигнатуры контейнеров и вычислил SHA-256.
Весь HTTP-прогон занял 21,64 секунды; [машиночитаемый отчёт](live-smoke-vds.json).

Таким образом, **3/4 реальных загрузок успешны**. Сетевая доступность YouTube
подтверждена, скачивание без авторизации с текущего IP не подтверждено. Для
следующей проверки нужна разрешённая сессия аккаунта. DRM/CAPTCHA не обходились.

- Compose корректно разобран и образы действительно собраны на Linux.
- API и worker имеют ограничения ресурсов; настроена ротация журналов.
- Проверены daily backup и восстановление всех четырёх заданий в отдельную БД.
- Тестовая БД восстановления удалена; основная БД сохранена.
- API и worker перезапущены; readiness восстановлен, задания сохранились.
- Автозапуск приложения и таймер резервирования включены в systemd.
- Ruff проходит. Исторический полный прогон приложения: 178 тестов, см. LIVE_TESTS.md.

## Подключение Telegram

После HTTP-прогона подключён Telegram-бот в отдельном контейнере:

- Токен проверен через `getMe`, webhook отсутствует; используется long polling.
- Владелец подтвердил аккаунт одноразовым сообщением в личном чате. В allowlist
  внесён один пользователь, без автоматического допуска произвольного первого отправителя.
- Бот использует отдельного клиента API `telegram`; доступ к API подтверждён HTTP 200.
- Административный API-ключ и мастер-ключ шифрования отсутствуют в окружении бота.
- Контейнер работает без перезапусков, systemd-автозапуск включён.
- Владелец проверил доставку файла из X; затем доставка изменена на встроенный
  видеоплеер, проверка описана ниже.

Автоматическая внешняя копия дампов пока не настроена; отдельная recovery-копия
ключей приложения сохранена на рабочем месте владельца.

## Видео с плеером в Telegram

13 ноября 2026 исправлена выдача результата: вместо MKV-документа воркер
готовит MP4 H.264/yuv420p + AAC с faststart, адаптер вызывает `sendVideo` с
`supports_streaming=true`. Совместимые потоки перепаковываются без перекодирования.
Другие кодеки преобразуются FFmpeg в пределах общих лимитов задания; отсутствие
звуковой дорожки допускается. До обновления сделаны резервные копии БД и исходников.

Проверена реальная ссылка
`https://x.com/iyiTriloji/status/2113881009892581687` без cookies:

- HTTP API → PostgreSQL → worker: `succeeded`, MP4, 1 948 199 байт.
- FFprobe: H.264, yuv420p, 320×568, AAC, длительность 50,759 с.
- `moov` находится перед `mdat`; полное декодирование FFmpeg: exit 0, ошибок нет.
- Через адаптер отправлено видео в подтверждённый личный чат владельца.
  Telegram вернул `Message.video`, без `Message.document`, MIME `video/mp4`,
  размер 1 948 199 байт, 320×568, длительность 51 с.
- Полный локальный прогон после запуска тестовой PostgreSQL: 184 теста прошли;
  дополнительная проверка сохранения выдачи старых MKV документом также прошла.
  Шесть новых проверок подготовки медиа используют настоящий FFmpeg.

Для другой присланной ссылки, `https://x.com/DNusina/status/2121201391783846207`,
GraphQL X вернул пустой `tweetResult`, а публичный syndication endpoint —
`TweetTombstone` с сообщением, что пост скрыт в Германии на основании местного
законодательства. Эта ссылка остаётся `unavailable`; это ограничение ответа X,
а не сбой Telegram или сетевой доступности VPS.
