# Проверка на отдельном VDS — 13 ноября 2026

Развёрнуто: Ubuntu 26.04 LTS, Docker Engine 29.9.3, Compose 5.7.1,
PostgreSQL 18, Python 3.12, yt-dlp 2026.10.26 + EJS, Node 24, FFmpeg.
Изменены только deployment-конфигурация и документация; код API и загрузчика
соответствует ранее протестированной версии 0.1.0.

## Сеть и готовность

- SSH-вход отдельным ключом проверен; ключ сервера закреплён для следующих входов.
- YouTube, X, Instagram, Vimeo, Telegram, GitHub и Docker Registry доступны
  с VDS по HTTPS. На этапе проверки сетевых таймаутов не было.
- PostgreSQL, API и worker запущены и имеют статус `healthy`.
- `/readyz` возвращает `200 {"status":"ready"}`.
- API доступен через локальный SSH-туннель; его порт и PostgreSQL не открыты наружу.

## Реальные загрузки

Клиент создал задания через HTTP API по SSH-туннелю и получил успешные
результаты через авторизованный endpoint выдачи файлов. Ни cookies, ни mock
загрузчики не использовались.

| Сервис | Публичный пример | Итог |
|---|---|---|
| YouTube | `https://www.youtube.com/watch?v=jNQXAC9IVRw` | `failed / auth_required`: сервис требует сессию для проверки «не бот» |
| X | `https://x.com/captainamerica/status/719944021058060289` | `succeeded`, 184 236 байт |
| Instagram | `https://www.instagram.com/reel/Chunk8-jurw/` | `succeeded`, 918 120 байт |
| Vimeo | `https://vimeo.com/22439234` | `succeeded`, 20 459 880 байт |

Все три полученных файла полностью декодированы FFmpeg с запрещёнными сетевыми
протоколами: exit code 0, stderr пуст. HTTP-клиент проверил размеры файлов,
сигнатуры контейнеров и вычислил SHA-256.
Весь HTTP-прогон занял 21,64 секунды; [машиночитаемый отчёт](live-smoke-vds.json).

Таким образом, **3/4 реальных загрузок успешны**. Сетевая доступность YouTube
подтверждена, скачивание без авторизации с текущего IP не подтверждено. Для
следующей проверки нужна разрешённая сессия аккаунта. DRM/CAPTCHA не обходились.

## Эксплуатационные проверки

- Compose корректно разобран и образы действительно собраны на Linux.
- API и worker имеют ограничения ресурсов; настроена ротация журналов.
- Проверены daily backup и восстановление всех четырёх заданий в отдельную БД.
- Тестовая БД восстановления удалена; основная БД сохранена.
- API и worker перезапущены; readiness восстановлен, задания сохранились.
- Автозапуск приложения и таймер резервирования включены в systemd.
- Ruff проходит. Исторический полный прогон приложения: 178 тестов, см. LIVE_TESTS.md.

Пользователь подтвердил, что Telegram-бот пока не создан. Бот в этом развёртывании
не запускался. Автоматическая внешняя копия дампов пока не настроена; отдельная
recovery-копия ключей приложения сохранена на рабочем месте владельца.
